# 고객 문의 자동화 — Google Sheets + Apps Script

문의 입력 → AI 분류·태그·답변 초안 → 검수 대기 → 사람이 최종 답변 작성 → 승인

## 설치

1. 새 Google 스프레드시트를 만듭니다.
2. **확장 프로그램 → Apps Script**를 열고 `Code.gs` 내용을 붙여넣어 저장합니다.
3. Apps Script에서 `setup` 함수를 선택하여 실행하고 Google 권한을 승인합니다. `문의`, `응대 정책` 탭이 생성됩니다. 기존 다른 탭은 그대로 유지됩니다.
4. **프로젝트 설정 → 스크립트 속성**에 `OPENAI_API_KEY`와 본인의 OpenAI API 키를 추가합니다. 키는 시트나 채팅에 입력하지 마세요. API 사용료는 별도입니다. 선택 속성 `OPENAI_MODEL`로 모델을 변경할 수 있으며 기본값은 `gpt-4.1-mini`입니다. 계정의 해당 모델 접근 권한이 필요합니다.
5. 시트를 새로고침합니다. **문의 자동화 → 샘플 문의 추가 → 지금 처리**를 실행하면 샘플 3건의 AI 결과가 생성됩니다.
6. `응대 정책` 탭에 실제 배송·환불·결제 정책을 입력합니다. 기본 문구는 확인되지 않은 사실을 확정하지 않는 원칙만 포함합니다.
7. **문의 자동화 → 자동 처리 시작 (5분)**을 실행합니다. 약 5분 간격으로 최대 5건을 처리합니다. 자동화 설치는 운영자 한 명이 담당하세요.

## 사용

- `문의` 탭의 **문의 내용(C열)**에 한 행당 문의 하나를 입력합니다. 상태는 비워두거나 `접수`로 지정합니다. ID와 접수일은 처리 시 자동 입력됩니다.
- AI가 분류(D), 태그(E), 우선순위(F), 초안(G), 검수 메모(H)를 채우고 상태를 `검수 대기`로 바꿉니다.
- 담당자는 초안을 확인하여 **최종 답변(J열)**에 수정본을 입력하고 **검수자(K열)**를 적습니다. 해당 행을 선택하고 **선택 문의 승인**을 실행하면 승인 상태와 검수일이 기록됩니다.
- 추가 확인이 필요하면 상태를 `보류`로 변경합니다. 고객에게 전달하는 작업은 별도로 수행합니다. 이 스크립트에는 발송 기능이 없습니다.
- 실패하면 `오류` 상태와 오류 설명이 표시됩니다. 원인을 수정한 뒤 해당 행을 선택하여 **선택 오류 재시도**를 실행합니다. 자동 재시도로 비용이 누적되지 않도록 오류 행은 자동 처리에서 제외합니다.
- **자동 처리 중지**는 현재 사용자가 설치한 이 자동화의 시간 트리거만 삭제합니다.

## 동작과 범위

- 입력 채널은 시트 직접 입력입니다. 이메일 수집·Google Forms 매핑·웹훅은 포함하지 않았습니다.
- 중복 실행은 스크립트 잠금으로 막고, 이미 초안이나 검수 기록이 있는 행은 재처리하지 않습니다.
- AI 요청 중 행 이동이나 내용 변경이 감지되면 결과를 폐기합니다. 처리 중에는 행 정렬·삭제를 피하고 필터 보기로 확인하세요. Google Sheets의 사람 편집과 스크립트 쓰기 사이에는 데이터베이스처럼 원자적 잠금이 없으므로 완전한 동시 편집 보장은 없습니다.
- 승인 메뉴는 최종 답변과 검수자를 요구합니다. 다만 시트 편집자는 상태를 직접 변경할 수 있으므로 이 예제는 엄격한 권한 분리나 변경 불가 감사 로그를 제공하지 않습니다.
- 문의 내용과 응대 정책이 OpenAI API로 전송됩니다. API 키는 스크립트 속성에 보관하지만 프로젝트 편집자는 접근할 수 있으므로 신뢰하는 운영자에게만 편집 권한을 주세요.
- `store:false`로 요청합니다. 모든 종류의 서비스 로그나 보관이 없어지는 의미는 아닙니다.
- 문의당 최대 12,000자, 정책 최대 16,000자입니다. 실행당 최대 5건이며 3분 경과 후에는 다음 문의를 시작하지 않습니다. 강제 실행 종료가 발생하면 접수 상태 문의가 다음 실행에서 다시 요청될 수 있습니다.
- 원문을 수정하여 재생성하려면 기존 결과를 별도로 보관한 뒤 D:H 및 J:M을 비우고 상태를 `접수`로 바꾸세요.

## 검증

로컬 테스트는 Node.js에서 `node test.cjs`로 실행하며 별도 패키지 설치가 필요하지 않습니다.

`build-dummy.mjs`는 가상 문의 20건이 담긴 Excel 파일과 미리보기 이미지를 생성하는 보조 스크립트입니다. Codex 환경의 `@oai/artifact-tool` 패키지가 필요하며, 일반 Node.js 환경에서는 해당 패키지 없이 실행할 수 없습니다. 결과는 프로젝트 상위 폴더의 `outputs/inquiry-dummy/`에 저장됩니다. Apps Script 설치와 로컬 테스트에는 이 스크립트가 필요하지 않습니다.

### 처리 로그 (inquiry-v2-log)

기존 Apps Script의 Code.gs를 새 버전으로 교체한 다음 `setup`을 한 번 실행하세요. 기존 문의 데이터는 유지됩니다. 이 저장소의 파일을 수정한 것만으로 Google에 설치된 코드가 바뀌지는 않습니다.

`처리 로그` 탭에서 문의 ID와 실행 ID를 필터링하면 AI 요청 시작 → AI 응답 수신 → 분류·태그·초안 저장을 추적할 수 있습니다. 요청 시 문의 원문과 정책을, 응답 시 생성된 결과와 모델·응답 ID·토큰 수를 저장합니다. 소요 시간은 해당 문의 처리 시작부터 이벤트 기록 직전까지의 밀리초입니다. 토큰 수는 응답 수신 이벤트와 저장 이벤트에 반복되므로 사용량 집계는 `AI 응답 수신`만 대상으로 하세요.

오류와 동시 편집으로 인한 결과 반영 취소도 기록합니다. 승인 메뉴는 초안·최종 답변·검수자 입력값과 승인 완료를 기록하며 재시도 메뉴도 요청·완료를 남깁니다. 이 검수자는 인증된 신원이 아니라 사람이 입력한 이름입니다.

셀 직접 편집·드롭다운 변경, 적용 전 이력, AI 내부 사고 과정은 기록하지 않습니다. 로그는 실제 실행에 따라 생성하며 샘플 성공 기록을 넣지 않습니다. 로그 쓰기에 실패하면 추가 처리를 중단합니다. 요청·응답·저장 로그와 실제 셀 수정은 하나의 원자적 트랜잭션이 아니므로 강제 종료 시 완료 로그가 없을 수 있습니다. 문의 상태와 Apps Script 실행 기록을 대조하세요. 설정 오류나 잠금으로 시작하지 못한 실행은 Apps Script 실행 기록에서 확인합니다.

로그에는 원문·정책·답변이 복사되며 시트 편집자가 수정할 수 있습니다. API 키는 기록하지 않습니다. 변경 불가 감사 기록이나 별도의 보관 만료 기능은 포함하지 않습니다.

`node test.cjs`로 실제 API 호출 없이 정상 응답, 미완료, 거절, HTTP 오류, 잘못된 분류, 수식 문자열, 처리 대상 상태를 검증합니다. 실제 Google 계정 설치와 유료 API 호출은 아직 실행하지 않았습니다. 설치 후 샘플 문의의 결과를 확인하고 최종 답변·검수자를 입력하여 승인까지 시험하세요.

공식 문서: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Apps Script 설치형 트리거](https://developers.google.com/apps-script/guides/triggers/installable).
